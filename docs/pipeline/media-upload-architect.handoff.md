# Architect Handoff: Media Upload (Presigned URL)

**Date**: 2026-02-24
**Agent**: architect
**Status**: COMPLETE

## What Was Designed

A single POST /api/v1/media/upload-url endpoint that generates an S3 presigned PUT URL for file uploads. The client sends a filename, content type, and media type (photo/audio/tts). The backend validates the content type against a per-type whitelist, sanitizes the filename, constructs an S3 key in the format `{type}/{user_id}/{uuid}_{filename}`, generates a 5-minute presigned PUT URL via boto3, and returns both the upload URL and the permanent file URL. No database tables are created or modified.

## Key Decisions

- **Presigned PUT over presigned POST**: PUT is simpler for mobile clients (single HTTP PUT with raw bytes, no multipart form encoding). This is the standard pattern for mobile-to-S3 uploads.

- **UUID in S3 key (not timestamp)**: The issue description specifies `{uuid}_{filename}`. UUID4 guarantees uniqueness without timestamp collision risk and prevents sequential enumeration. This differs from `docs/09-dagitim.md` which shows `{timestamp}_{filename}`, but the issue description takes precedence.

- **Per-type content type whitelist**: Photo types cannot accept audio MIME types and vice versa. The whitelist is: photo (image/jpeg, image/png, image/heic), audio (audio/m4a, audio/mp3, audio/mpeg), tts (audio/mp3, audio/mpeg). Both `audio/mp3` and `audio/mpeg` are accepted since some clients use the non-standard `audio/mp3`.

- **10 MB limit via S3 bucket policy (not presigned URL)**: The `generate_presigned_url` PUT method does not support `ContentLengthRange` conditions. File size enforcement is delegated to S3 bucket policy (infrastructure concern). The 10 MB limit is documented as a contract for clients.

- **Filename sanitization over rejection**: Filenames from mobile camera rolls often contain spaces and special characters. Sanitizing (replace spaces, strip path traversal, truncate) is more user-friendly than rejecting.

- **Module-level boto3 client**: Unlike Mem0 (instantiated per-call), the boto3 S3 client is designed for reuse with internal connection pooling. Created once at module level.

- **No database writes**: File metadata is not stored in a separate table. The `file_url` is associated with a message when the user sends it via `POST /characters/:id/messages` (stored in `messages.media_url` or `messages.tts_url`).

- **5-minute presigned URL expiration**: Sufficient time for mobile upload while limiting the window for URL leakage.

- **No new config values needed**: `s3_bucket_name` and `aws_region` already exist in `config.py`.

## Assumptions Made

- The S3 bucket (`s3_bucket_name` in config.py) already exists and the ECS task role has `s3:PutObject` and `s3:GetObject` permissions.
- The S3 bucket has "Block Public Access" enabled. File access is via presigned URLs or CloudFront.
- The boto3 credential chain (IAM role on ECS Fargate, or environment variables in local dev) is already configured.
- Mobile clients handle image compression before upload (per `docs/08-guvenlik-performans.md`: max 1MB, HEIF to JPEG on iOS, WEBP on Android).
- The 10 MB file size limit will be enforced via S3 bucket policy by the DevOps team (outside this feature's scope).
- The `file_url` format (`https://{bucket}.s3.{region}.amazonaws.com/{key}`) is accessible. If CloudFront is in front of S3, a URL rewrite may be needed later (not in this feature).

## Notes for Developers

### For backend-dev

1. Start with schemas (`app/schemas/media.py`), then the service (`app/services/media_service.py`), then the route (`app/routes/media.py`), then wire up in `main.py`.

2. The boto3 `generate_presigned_url("put_object", ...)` method is a LOCAL computation (HMAC signing). It does not make network calls. No `asyncio.to_thread()` wrapping is strictly needed, but is acceptable for consistency.

3. The `ALLOWED_CONTENT_TYPES` whitelist should be a module-level dict constant in `media_service.py`.

4. Do NOT log the presigned URL -- it contains AWS credentials in query parameters.

5. The `main.py` import line needs `media` added and the router registered with prefix `/api/v1/media`.

### For backend-tester

1. No database setup is needed for tests. Only mock `get_current_user` and `boto3`.

2. Test all valid content_type + type combinations (8 valid combos) and several invalid ones.

3. Parametrize filename edge cases: spaces, path traversal, Unicode, empty-after-trim, very long names.
